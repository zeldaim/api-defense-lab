# 룰 공장 — 로컬 LLM이 룰을 쓰고 연습장이 채점한다 (2026-11-26)

**한 줄**: 로컬 7B 모델(Qwen2.5-7B-Instruct)은 포기할 선택지가 있으면 거의 항상 포기하고(첫 시도 포기 39/40, 합격 0/40), 포기할 수 없게 하면 **유효한 룰은 낸다(40/40) 하지만 보지 못한 변종까지 일반화되는 룰은 드물다** — BOLA 3/20, 탐색 4/20. 사람이 만든 단순 임계값 하나(같은 IP가 30초에 404를 5번)는 둘 다 통과한다.

표본이 작고(조건당 20회), 모델 하나·시나리오 둘·합성 변종이다. 비율이 아니라 **구간(95% 신뢰구간)과 분포**로 읽을 것.

## 무엇을 쟀나

LLM이 접속 로그 증거(공격자·정상 요약, 코드가 계산)를 보고 **정해진 스키마의 룰 하나**를 낸다(필드 5개 · 수정자 4개 · 빈도 조건). 룰은 신뢰할 수 없는 코드로 취급한다(정규식 길이 · 중첩 반복 차단, 채점 시간 제한). **합격 여부는 코드가 정한다.**

| 시나리오 | 공격 | 왜 어렵나 |
|---|---|---|
| `bola` | 다른 사용자의 객체 ID를 순서대로 열거 | 경로(`/orders/{n}`)가 정상 사용자도 쓰는 명세 안 경로라 경로만으로는 구분이 안 된다. 기존 경로 룰이 못 잡는다 |
| `probe` | 명세에 없는 숨은 경로 탐색 | 매번 다른 경로를 두드릴 수 있다 |

**평가 설계 (실행 전에 코드에 고정한 값)**

- **학습** `fast1`: LLM이 보는 증거와 재시도 피드백은 여기서만 만든다.
- **보지 못한 구간 A** `fast2·fast3·slow1·slow2`: 같은 생성기의 다른 실행, **모든 IP를 무작위 주소로 바꿈**.
- **보지 못한 구간 B(변종, 합성)**: `fast2`에 학습 때 보여주지 않은 새 탐색 경로 15개와 다른 경로(`/orders/status/{n}`)의 BOLA를 주입(내가 만든 것). 간격·상태 코드 분포는 실제 공격자에서 가져왔다.
- **합격** = 학습·구간 A·변종 B 모두에서 목표 공격자를 전부 탐지하고 정상 오탐 행위자 0명.
- **안티치트**: 스키마에서 `c-ip`를 뺐다(연습장은 정상 10.10 · 탐색 10.66 · BOLA 10.77로 IP 대역이 역할과 겹쳐 외우면 만점이 나온다 — `docs/benchmark-design.md` §1). 아래 기준선의 "치트" 룰이 원본 IP에서는 만점, IP 무작위화 후에는 0으로 무너지는 것으로 확인했다.

**읽는 법**

- **사전 지정 조건에서 합격은 0/40(GPU)** — 거의 항상 포기한다. 이건 모델 능력이 아니라 "포기해도 된다"는 선택지를 과하게 쓰는 습관이다. 포기하면서 채운 초안 중 일부는 쓸 만했지만(보고서 `report` 의 "스스로 포기한 시도" 줄) 합격 판정에는 쓰지 않았다.
- **포기를 없애면** 유효한 룰이 40/40 나온다. 그러나 **BOLA는 20회 중 17회가 학습은 통과하고 변종에서 실패**(경로를 외움 — 구간 A 통과는 19/20이라 같은 생성기에서는 잘 통한다), 탐색은 20회 중 9회만 학습을 통과한다.
- **CPU 6회 추정은 낙관적이었다**: 탐색 합격이 CPU 3/6(50%)에서 GPU 20회 4/20(20%)로 내려왔다. 신뢰구간은 겹친다(19–81% vs 8–42%) — 6회로는 구별이 안 된다는 뜻이다.
- **CPU와 GPU는 같은 시드에서도 다른 룰을 낸다**: 첫 시도 룰이 완전히 같은 경우는 24회 중 3회. 합격 여부가 같은 건 24회 중 20회. LLM 평가는 하드웨어에 따라 출력이 달라지므로 한 환경의 수치를 다른 환경에 그대로 옮기면 안 된다.

- **사람 룰(레포 `rules/sigma`)**: 탐색은 잡고 BOLA는 못 잡는다(예상대로).
- **치트(IP 대역)**: 원본 IP에서 만점, IP 무작위화 후 0 — 채점기의 누수가 실재했고 무작위화가 막는다.
- **암기(학습 탐색 경로)**: 같은 생성기에서는 통과하지만 변종 탐색에서 갈린다. (BOLA 열의 1/1은 우연: 외운 경로 중 `/orders/1`을 BOLA 공격자가 순서대로 훑을 때 지나간다.)
- **단순 임계값(같은 IP 404 5회/30초)**: 탐색·BOLA 변종을 전부 잡고 정상 오탐 0. **이 시나리오가 생각보다 쉽다는 뜻이고, 모델의 합격률은 이 기준선과 비교해야 한다.**
- **BOLA형(`/orders/N` 404 10회/60초)**: 원래 BOLA는 잡지만 다른 경로의 변종은 놓친다 — LLM이 낸 룰들과 같은 실패 방식.

## 수정 이력 (숨기지 않는다)

1. 스모크 테스트에서 **내 코드 버그** 발견: 스키마를 펼치는 함수가 메타데이터 `title`과 함께 `title`이라는 이름의 속성까지 지워 LLM에게 `title` 칸이 없는 스키마가 갔다. 고친 뒤 본 실행.
2. 기준선 "암기" 룰이 정상도 쓰는 경로를 포함해 정상 20명을 오탐 → 정상 트래픽에 없는 경로만 외우도록 정의를 고침(본 실행 전).
3. LLM이 포기를 선언하면서 초안을 채워 넣는 경우를 따로 기록하게 함(합격 기준은 그대로 — 포기=실패).
4. **채점 로직 버그**: 구간 A의 `slow1·slow2`에는 탐색 공격자가 없어 "목표를 전부 탐지"가 공허하게 실패로 처리됐다. 오탐만 보도록 고치고 저장된 초안을 **재채점**했다(원본은 `cpu_main/*.raw.jsonl` 로 보존). 이 수정으로 CPU 사전 지정 탐색의 합격이 0/6에서 1/6으로 바뀌었다.
5. "포기 불가" 조건은 사전 지정 결과를 본 **뒤에** 만든 사후 탐색 조건이다.
6. GPU 실행은 CPU 이후에 했다. 코드·시드 규칙은 같다.

## 한계

- **모델 하나**(Qwen2.5-7B-Instruct), 시나리오 둘, 조건당 20회. 더 큰 모델이면 결과가 다를 수 있다 — 안 쟀다.
- **변종은 내가 만든 합성**이다. 실제 새 공격이 아니다. 학습·구간 A도 같은 생성기에서 나온 데이터다.
- 세트당 공격자가 1명이라 행위자 수준 표본이 매우 작다(공격 요청 수 17~152개).
- 룰은 **단건·빈도 조건만** 표현할 수 있다. 개별 객체 ID가 겹치는지(distinct) 같은 조건은 엔진이 지원하지 않는다.
- 합격 룰이 실제 운영에서 좋다는 뜻이 아니다. 이 생성기와 이 변종에 대해서만 말한다.
