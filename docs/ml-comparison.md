# ML 모델 비교 — 왜 IsolationForest 였나, 다른 모델이면? (2026-11-22)

detector 는 IsolationForest 하나만 써 왔다. **고른 근거(비교)가 없었다.** 그래서 같은 조건에서 6개를 붙여 봤다.

## 결론

1. **이 연습장의 BOLA 는 모든 모델이 똑같이 잡는다.** 차단 시각은 모델이 아니라 **차단 정책(그 창 요청 N건 이상)** 이 정한다. 새어 나간 주문 수도 6개 모델이 한 건도 다르지 않다.
2. 모델 차이는 **정상 사용자 쪽(소음 · 오탐)** 에서만 났다.
   - **통계 기준선(RobustZ)** 이 IsolationForest 와 탐지는 같고 정상 high 창은 더 적었다 (5 vs 14/300). 이 연습장에서는 "더 복잡한 모델"을 고를 근거가 없다.
   - **One-Class SVM · 오토인코더는 정상 100명 전부를 막았다.** 학습 데이터(11-18 정상 트래픽)와 오늘 정상 트래픽의 작은 차이에도 무너진다 — 학습 점수로 정한 임계값이 옮겨 가지 않는다.
   - **지금 쓰는 dvra_v1 은 정상 1명을 잘못 막았다** (같은 규칙으로 다시 학습한 IsolationForest 는 0).
3. **유출을 줄이는 손잡이는 모델이 아니라 정책이다.** 창 요청 기준을 15 → 10 으로 내리면 유출이 39 → 24 (빠른 BOLA) · 26 → 16 (느린 BOLA) 로 줄고 오탐은 0~1 → 2명. 5 로 내리면 유출 9 · 6 이지만 **정상 100명이 모두 막힌다** (짧은 창 오탐 — 알려 둘 한계에 적었던 그것). LOF 만 5 에서도 10명으로 버텼다.
4. ~~지금 쓰는 dvra_v1 은 이 레포 코드로 똑같이 다시 만들 수 없다~~ **고침 (2026-11-25).** 당시 동봉 모델은 기록(`model_meta.json`)과 같은 범위로 학습 창을 뽑으면 365개가 아니라 394개, 특징 분포도 달랐다(예: `uniq_path_ratio` 99 백분위 0.64 → 0.575) — 특징 코드가 바뀌기 전 버전으로 학습된 것으로 보였다. `docker compose run --rm traffic normal --users 25 --rounds 50 --pause 1.0`(정상 트래픽, 약 24분) → `docker compose --profile tools run --rm trainer`로 새로 학습(창 149개)해 `model/dvra_v1`을 교체했다 — probe 1.6초, BOLA 7.6초 차단, 정상 20명 오탐 0으로 확인(README "기본 설정 결과"). 이제 README의 트레이너 명령 그대로 다시 만들 수 있다. `model_meta.json`의 `reproducible_note`에 재현 절차를 적어 뒀다.

## 설정 — 모든 모델에 같게

| 항목 | 값 |
|---|---|
| 학습 데이터 | dvra_v1 과 같은 정상 트래픽 로그, `model_meta.json` 의 학습 창 범위 → 창 394개 (`docs/results/ml-compare_2026-11-22/train_normal.log`) |
| 학습 거르기 | 오류 비율 0.3 미만 · 요청 1500 미만 · 명세 밖 호출 없음 (`detector/train.py` 와 같음) |
| 임계값 | 학습 창 점수의 0.5 백분위 = high (모든 모델 같은 규칙) |
| 평가 트래픽 | 연습장 5번 — 데모 3번(정상 20명 + 탐색 + 빠른 BOLA 0.4초 간격) · 느린 BOLA 2번(2.5초 간격 + 정상 20명). **차단을 끄고** 돌려 공격이 끝까지 기록되게 (`eval/`) |
| 채점 | live detector 흉내: 요청 하나마다 그 순간 진행 중인 5분 창을 채점, 처음으로 "high 이고 창 요청 N건 이상" = 차단. 그때까지 받은 2xx(가입 · 로그인 제외) = 새어 나감 |
| 후보 | dvra_v1(동봉, 다시 학습 안 함) · IsolationForest(같은 설정 재학습) · RobustZ(특징별 중앙값 · MAD 거리) · LOF · One-Class SVM · Elliptic Envelope · 오토인코더 — `detector/models_extra.py` |

## 다시 돌리기

```bash
docker compose build trainer        # 도구 이미지 (scikit-learn 1.5.2)
docker run --rm -v "$PWD:/repo:ro" -v "$PWD/out:/out" api-defense-lab/tools:0.1 \
  python /repo/tools/ml_compare.py --train /repo/docs/results/ml-compare_2026-11-22/train_normal.log \
  --eval /repo/docs/results/ml-compare_2026-11-22/eval --out /out \
  --like /repo/model/dvra_v1/model_meta.json --block-min-req 15 [--save-models /out/models]
```

`--save-models` 로 저장한 모델은 `model.joblib` · `model_meta.json` 꼴이라 `LAB_MODEL` 로 detector 에 그대로 끼울 수 있다 (`models_extra.py` 의 클래스는 detector 폴더에 있어 불러올 수 있음).

## 한계 — 이 표로 말할 수 없는 것

- **공격이 너무 쉽다.** BOLA 가 연속 ID 를 한 IP 로 훑는다 — 어떤 모델이든 첫 창에서 튄다. 모델 차이를 보려면 더 어려운 공격이 필요하다: ID 를 섞어 훑기 · 여러 IP 로 나누기 · 정상 사용자 흉내 섞기.
- **오프라인 흉내다.** live detector 는 2초마다 채점하는데 여기서는 요청마다 채점한다 (모든 모델에 같은 방식이라 비교는 공정하지만 절대 시간은 실제와 조금 다르다). 정책 15 의 숫자는 레이트 리밋 실험의 실제 실행(빠른 BOLA 유출 11~18 · 느린 14)과 같은 크기다.
- **One-Class SVM · 오토인코더가 나쁘다는 결론이 아니다.** "학습 점수 0.5 백분위" 임계값 규칙 아래에서 무너졌다는 것. 정상 데이터 일부를 떼어 임계값을 다시 맞추면(보정) 달라질 수 있다 — 하지만 그만큼 운영이 손이 간다는 뜻이기도 하다.
- 학습 · 평가가 **합성 트래픽**이다. 평가 5번 · 학습 데이터 1벌.
